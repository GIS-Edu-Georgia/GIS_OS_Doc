## 🗺️ Project 1. Building density map

**The task.** We have 3,500 points (buildings) across Georgia, clustered around three cities, plus scattered background points. For a web map we need to count the density in tiles at every zoom.

!!! question "Steps"
    1. Convert every point into the quadkey of its **z=12** tile.
    2. Using quadkey prefixes, count the points at levels z=8, 10 and 12 (`Counter`). Which tile is the busiest at each level?
    3. Check that the value of every z=8 tile equals the sum of its z=10 children.
    4. Find what percentage of the z=12 tiles in the area's grid are occupied.

??? success "Solution"
    ```python title="density.py" linenums="1"
    import math
    import random
    from collections import Counter

    random.seed(7)
    centers = [(44.80, 41.72, 0.05), (41.64, 41.65, 0.04), (43.58, 42.25, 0.03)]   # Tbilisi, Batumi, Kutaisi (approximately)
    pts = [(random.gauss(cx, s), random.gauss(cy, s))
           for cx, cy, s in (random.choice(centers) for _ in range(3000))]
    pts += [(random.uniform(40.0, 46.7), random.uniform(41.0, 43.6)) for _ in range(500)]


    def lonlat_to_tile(lon, lat, z):
        n = 2 ** z
        x = int((lon + 180) / 360 * n)
        y = int((1 - math.asinh(math.tan(math.radians(lat))) / math.pi) / 2 * n)
        return min(x, n - 1), min(y, n - 1)


    def quadkey(x, y, z):
        key = ''
        for i in range(z, 0, -1):
            mask = 1 << (i - 1)
            key += str((1 if x & mask else 0) + (2 if y & mask else 0))
        return key


    keys = [quadkey(*lonlat_to_tile(lon, lat, 12), 12) for lon, lat in pts]

    for z in (8, 10, 12):
        cnt = Counter(k[:z] for k in keys)
        key, n = cnt.most_common(1)[0]
        print(f'z={z:2}: occupied tiles {len(cnt):3}, busiest {key} -> {n}')

    # hierarchy: parent value = sum of its children
    c8, c10 = Counter(k[:8] for k in keys), Counter(k[:10] for k in keys)
    ok = all(c8[p] == sum(v for k, v in c10.items() if k.startswith(p)) for p in c8)
    print('parent = sum of children:', ok)

    # share of empty tiles at z=12 in this area
    x0, y1 = lonlat_to_tile(40.0, 41.0, 12)
    x1, y0 = lonlat_to_tile(46.7, 43.6, 12)
    total = (x1 - x0 + 1) * (y1 - y0 + 1)
    print(f'the z=12 grid has {total} tiles, {len(set(keys))} occupied ({100 * len(set(keys)) / total:.1f}%)')
    ```
    ```text
    z= 8: occupied tiles  18, busiest 12033323 -> 1048
    z=10: occupied tiles 184, busiest 1203332312 -> 1011
    z=12: occupied tiles 489, busiest 120333303311 -> 452
    parent = sum of children: True
    the z=12 grid has 3157 tiles, 489 occupied (15.5%)
    ```
    **What we see.** A quadkey prefix is exactly the parent tile, so a single count (at z=12) is enough: the other levels are obtained from it by truncating the prefix. Only 15.5% of the grid is occupied, so we do not store the empty tiles at all (this is the advantage of a quadtree: **memory depends on the data, not on the area**).

## 📍 Project 2. Nearest station

**The task.** There are 2,000 stations, and for 2,000 addresses we need to find the nearest station. A direct search checks every station for each query; a k-d tree never visits most of the branches.

!!! question "Steps"
    1. Write `brute(q)`: `min` over all stations.
    2. Build a k-d tree and `nearest` ([Indexes](spatial_indexes.md)).
    3. Make sure both methods return the same station for every address.
    4. Measure the time with `time.perf_counter()` and compute the speed-up.

??? success "Solution"
    ```python title="nearest_station.py" linenums="1"
    import random
    import time

    random.seed(3)
    stations = [(random.uniform(0, 100), random.uniform(0, 100)) for _ in range(2000)]
    queries = [(random.uniform(0, 100), random.uniform(0, 100)) for _ in range(2000)]


    def brute(q):
        return min(stations, key=lambda s: (s[0] - q[0]) ** 2 + (s[1] - q[1]) ** 2)


    def build(points, depth=0):
        if not points:
            return None
        axis = depth % 2
        points = sorted(points, key=lambda p: p[axis])
        mid = len(points) // 2
        return (points[mid], axis, build(points[:mid], depth + 1), build(points[mid + 1:], depth + 1))


    def nearest(node, t, best=None):
        if node is None:
            return best
        p, axis, left, right = node
        d = (p[0] - t[0]) ** 2 + (p[1] - t[1]) ** 2
        if best is None or d < best[1]:
            best = (p, d)
        diff = t[axis] - p[axis]
        near, far = (left, right) if diff < 0 else (right, left)
        best = nearest(near, t, best)
        if diff * diff < best[1]:
            best = nearest(far, t, best)
        return best


    tree = build(stations)
    t0 = time.perf_counter()
    a = [brute(q) for q in queries]
    t1 = time.perf_counter()
    b = [nearest(tree, q)[0] for q in queries]
    t2 = time.perf_counter()
    print('identical:', a == b)
    print(f'speed-up ≈ {(t1 - t0) / (t2 - t1):.0f}x')
    ```
    ```text
    identical: True
    speed-up ≈ 70x
    ```
    The speed-up will be different on your computer, but of a similar order (tens of times). Note that we did **not** count the time to build the tree: it is spent once and then serves every query.

!!! question "Going further"
    Increase the number of stations from 200 to 20,000 and plot how the speed-up depends on `n`. Why does the speed-up grow with `n`? (Hint: `O(n)` vs `O(log n)`.)

## 🧭 Project 3. Mini-navigator

**The task.** A 40×60 cell map has obstacles (buildings, walls). We need to find the shortest path from `(2,2)` to `(37,57)` and simplify it so that only the main turning points remain.

!!! question "Steps"
    1. Build an 8-neighbour graph in which **cutting a corner diagonally past an obstacle is not allowed**.
    2. Find the path with A* using the octile heuristic. How many cells were expanded?
    3. Simplify the path with Douglas–Peucker at `ε=1`.
    4. Check whether the simplified line crosses an obstacle. Try `ε = 0.5, 1, 2, 3`.

??? success "Solution"
    ```python title="navigator.py" linenums="1"
    import heapq
    import math
    import random

    random.seed(11)
    R, C = 40, 60
    cost = [[None if random.random() < 0.22 else 1.0 for _ in range(C)] for _ in range(R)]
    for r in range(5, 35):
        cost[r][20] = None                    # vertical walls
    for r in range(0, 30):
        cost[r][40] = None
    for r, c in [(20, 20), (3, 40), (2, 2), (37, 57)]:
        cost[r][c] = 1.0                      # a door in each wall, the start and goal cells


    def neighbors(r, c):
        for dr in (-1, 0, 1):
            for dc in (-1, 0, 1):
                if dr == dc == 0:
                    continue
                rr, cc = r + dr, c + dc
                if not (0 <= rr < R and 0 <= cc < C) or cost[rr][cc] is None:
                    continue
                if dr and dc and (cost[r][cc] is None or cost[rr][c] is None):
                    continue                  # corner cutting is not allowed
                yield (rr, cc), math.hypot(dr, dc) * cost[rr][cc]


    def octile(a, b):
        dr, dc = abs(a[0] - b[0]), abs(a[1] - b[1])
        return (dr + dc) + (math.sqrt(2) - 2) * min(dr, dc)


    def astar(start, goal):
        g = {start: 0}
        prev = {}
        heap = [(octile(start, goal), start)]
        done = set()
        while heap:
            _, u = heapq.heappop(heap)
            if u in done:
                continue
            done.add(u)
            if u == goal:
                break
            for v, w in neighbors(*u):
                ng = g[u] + w
                if ng < g.get(v, math.inf):
                    g[v] = ng
                    prev[v] = u
                    heapq.heappush(heap, (ng + octile(v, goal), v))
        if goal not in g:
            return None, None, len(done)
        path = [goal]
        while path[-1] != start:
            path.append(prev[path[-1]])
        return path[::-1], g[goal], len(done)


    def point_line_distance(p, a, b):
        (x, y), (x1, y1), (x2, y2) = p, a, b
        if a == b:
            return math.hypot(x - x1, y - y1)
        return abs((x2 - x1) * (y1 - y) - (x1 - x) * (y2 - y1)) / math.hypot(x2 - x1, y2 - y1)


    def douglas_peucker(pts, eps):
        if len(pts) < 3:
            return pts
        d, i = max((point_line_distance(pts[k], pts[0], pts[-1]), k) for k in range(1, len(pts) - 1))
        if d <= eps:
            return [pts[0], pts[-1]]
        return douglas_peucker(pts[:i + 1], eps)[:-1] + douglas_peucker(pts[i:], eps)


    def line_cells(a, b):
        n = int(max(abs(b[0] - a[0]), abs(b[1] - a[1])) * 2) + 1
        return {(round(a[0] + (b[0] - a[0]) * i / n), round(a[1] + (b[1] - a[1]) * i / n)) for i in range(n + 1)}


    path, length, expanded = astar((2, 2), (37, 57))
    print(f'path: {len(path)} cells, length {length:.2f}, {expanded} cells expanded')

    for eps in (0.5, 1, 2, 3):
        simp = douglas_peucker(path, eps)
        bad = sum(any(cost[r][c] is None for r, c in line_cells(simp[i], simp[i + 1]))
                  for i in range(len(simp) - 1))
        print(f'ε={eps}: {len(simp):2} points, {bad} segment(s) cross an obstacle')
    ```
    ```text
    path: 82 cells, length 86.38, 580 cells expanded
    ε=0.5: 24 points, 0 segment(s) cross an obstacle
    ε=1: 10 points, 1 segment(s) cross an obstacle
    ε=2:  6 points, 3 segment(s) cross an obstacle
    ε=3:  6 points, 3 segment(s) cross an obstacle
    ```
    **The main conclusion.** Douglas–Peucker takes only the shape of the line into account and **knows nothing about obstacles**. At `ε=1` the simplified line already crosses a wall. In navigation, simplification must either stop at the first violation (increasing `ε` only while the path stays clear) or be checked again afterwards. This is a typical case where two correct algorithms together give a wrong result.

## ⏱️ Project 4. Reachability zone

**The task.** On the same map we want to know **where we can get from the cell at column 10, row 20 within cost `T`**. The zone should be outlined with a polygon and its area found.

!!! question "Steps"
    1. Modify Dijkstra so that it stops when the cost exceeds `T` (all cells with `d ≤ T`).
    2. Take the `(x, y) = (column, row)` coordinates of these cells and build their **Convex hull**.
    3. Compute the hull's area with the shoelace formula.
    4. For `T = 5, 10, 15`, compare the hull area with the number of cells reached. What does this ratio mean?

??? success "Solution"
    Add this code to the **end** of `navigator.py` from the previous project (same `cost`, `neighbors`):

    ```python title="isochrone.py" linenums="1"
    def dijkstra_limit(start, limit):
        dist = {start: 0}
        heap = [(0, start)]
        done = set()
        while heap:
            d, u = heapq.heappop(heap)
            if u in done:
                continue
            done.add(u)
            for v, w in neighbors(*u):
                nd = d + w
                if nd <= limit and nd < dist.get(v, math.inf):
                    dist[v] = nd
                    heapq.heappush(heap, (nd, v))
        return dist


    def convex_hull(points):
        pts = sorted(set(points))

        def cross(o, a, b):
            return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

        lower, upper = [], []
        for p in pts:
            while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
                lower.pop()
            lower.append(p)
        for p in reversed(pts):
            while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
                upper.pop()
            upper.append(p)
        return lower[:-1] + upper[:-1]


    def polygon_area(poly):
        s = sum(poly[i][0] * poly[(i + 1) % len(poly)][1] - poly[(i + 1) % len(poly)][0] * poly[i][1]
                for i in range(len(poly)))
        return abs(s) / 2


    start = (20, 10)
    for limit in (5, 10, 15):
        dist = dijkstra_limit(start, limit)
        hull = convex_hull([(c, r) for r, c in dist])
        area = polygon_area(hull)
        print(f'T={limit:2}: reached {len(dist):3} cells, hull {len(hull):2} vertices, area {area:.1f}, ratio {len(dist) / area:.2f}')
    ```
    ```text
    T= 5: reached  42 cells, hull  7 vertices, area 46.0, ratio 0.91
    T=10: reached 170 cells, hull 11 vertices, area 211.5, ratio 0.80
    T=15: reached 374 cells, hull 13 vertices, area 443.0, ratio 0.84
    ```
    **What the ratio means.** Without obstacles the zone would be a circle (an octagon in the octile metric) and the ratio would approach 1. The fact that this number is below 1 means the hull also includes places we cannot actually reach (behind walls). A convex hull is a simple but coarse outline: a real reachability zone is often **not round**, and a concave hull or a union of cells works better.
