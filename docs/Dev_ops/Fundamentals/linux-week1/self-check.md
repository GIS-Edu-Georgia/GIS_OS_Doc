**პასუხები** ქვემოთაა (6ა). ჯერ პასუხი თქვი, მერე შეადარე.


# პასუხები თვითშემოწმების კითხვებზე

**როგორ გამოიყენო:** წაიკითხე კითხვა, **დაფარე პასუხი**, თქვი შენი სიტყვებით, მერე შეადარე. რომელზეც ვერ უპასუხე, მონიშნე და ისევ გაიმეორე.

**1. რომელია კლიენტი და რომელი სერვერი? სად სრულდება ბრძანება?**
კლიენტი = შენი კომპიუტერი, სერვერი = VM. ბრძანება **სერვერზე სრულდება**, კლიენტს მხოლოდ შედეგი ბრუნდება SSH სესიით.

**2. რომელი გასაღები არ უნდა გაგიზიარებია და რატომ?**
**პირადი**. ვისაც ის ექნება, შენი სახელით შევა სერვერზე. საჯარო უსაფრთხოდ გადაეცემა და სერვერზე დევს.

**3. რას იძლევა `ssh-keygen -lf`?**
გასაღების **fingerprint-ს** (მოკლე კოდს). ვადარებთ, რომ სერვერზე ჩაწერილი გასაღები ზუსტად ის არის, რაც შევქმენი.

**4. რით განსხვავდება `>` და `>>`?**
`>` **ზედმიწერს** (ძველი იკარგება), `>>` **ბოლოში ამატებს** (ძველი რჩება).

**5. რას აკეთებს `mkdir -p a/{b,c}/d`?**
ქმნის `a/b/d` და `a/c/d`. `-p` მშობლებსაც ქმნის და არსებულზე არ ჩივის.

**6. რატომ არ ეშველება `.env` ფაილს სახელის წინ წერტილი?**
წერტილი მხოლოდ ზოგად `ls`-ს ეუბნება, რომ არ აჩვენოს. `ls -a` ან `cat .env` მაინც აჩვენებს. დაცვა არის **უფლებები**.

**7. რას ნიშნავს `-rw-r-----` და რა რიცხვია?**
მფლობელი `rw-` (წაკითხვა + ჩაწერა), ჯგუფი `r--` (მხოლოდ წაკითხვა), სხვები `---` (არაფერი). რიცხვი **`640`**.

**8. რატომ ვერ გავიდა `cd secret-dir`, თუმცა `ls secret-dir` იმუშავა?**
დირექტორიაზე `r` = სახელების ჩამოთვლა (`ls` იმუშავა), `x` = **შესვლა** (`cd` ვერ გავიდა, რადგან `x` აკლდა).

**9. `report.txt` და `Report.txt` ერთი ფაილია?**
არა. Linux **რეგისტრს არჩევს**, ეს ორი სხვადასხვა ფაილია.

**10. რატომ ვხსნით `"final report.txt"` ბრჭყალებში?**
გამოტოვება shell-ისთვის გამყოფია. ბრჭყალების გარეშე ორ სხვადასხვა სახელად (`final` და `report.txt`) აღიქვამდა.

**11. რას აკეთებს `cp -r a b` და რას `mv a b`?**
`cp -r` აკოპირებს საქაღალდეს (ორიგინალი **რჩება**). `mv` **გადააქვს** ან გადაარქმევს (წყაროდან **ქრება**).

**12. რატომ არ კმარა `grep ERROR` ნამდვილი შეცდომების გამოსაყოფად?**
`grep` ხაზის ნებისმიერ ადგილას ეძებს, ამიტომ INFO ხაზსაც დაიჭერდა, რომლის message-შიც `ERROR` წერია. ვამოწმებთ **level ველს**: `awk '$2=="ERROR"'`.

**13. რას აკეთებს `awk '$2=="ERROR"' f`?**
ტოვებს მხოლოდ იმ ხაზებს, სადაც **მეორე ველი** (level) არის `ERROR`.

**14. რას აკეთებს `|`? აღწერე `awk ... | sort | uniq`.**
`|` ერთი ბრძანების გამოტანას მეორეს შესატანად გადასცემს. `awk` ამოიღებს service-ებს → `sort` ალაგებს → `uniq` განმეორებებს აშორებს (შედეგი: `api`, `db`).

**15. რას აკეთებს `sed -i 's/^PORT=.*/PORT=9090/' f`?**
ფაილში **ადგილზე** ცვლის ხაზს, რომელიც `PORT=`-ით იწყება, ახალი `PORT=9090`-ით. ფაილს თავიდან არ ქმნის.

**16. რით განსხვავდება `rmdir` და `rm -r` და რატომაა ასლი წინასწარ მნიშვნელოვანი?**
`rmdir` მხოლოდ **ცარიელს** წაშლის, `rm -r` შიგთავსიანსაც. ტერმინალში წაშლა **საბოლოოა**, სანაგვე ყუთი არ არსებობს, ამიტომ ჯერ ასლი.

**17. რას ნიშნავს `current -> releases/v2` და როგორ გადაერთვება v1-ზე?**
`current` არის სიმბოლური ბმული, რომელიც `releases/v2`-ზე მიუთითებს. გადართვა: `ln -sfn releases/v1 current`.

**18. რატომ არ ამტკიცებს ბმულის არსებობა სამიზნის არსებობას?**
ბმული მხოლოდ **გზაა** და სამიზნეს არ ამოწმებს. `current -> releases/v9` თვითონ არსებობს, `v9` კი არა, ანუ ბმული გატეხილია.

**19. რას აკეთებს `tar -czf`, `tar -tzf`, `tar -xzf`?**
`-czf` ქმნის შეკუმშულ არქივს, `-tzf` აჩვენებს შემადგენლობას **ამოღების გარეშე**, `-xzf` ამოიღებს.

**20. როგორ დაამტკიცე, რომ აღდგენილი ფაილი თავდაპირველის ტოლია?**
წაშლამდე `sha256sum`-ით **ანაბეჭდი ჩავიწერე**, ფაილი წავშალე, **არქივიდან აღვადგინე** და `sha256sum -c`-მ დაწერა **OK**, ანუ ბაიტ-ბაიტ იგივეა. (ასლი = არქივი; ანაბეჭდი = მოკლე კოდი შესადარებლად.)

**21. რატომ არ გამოიყენება `chmod 777`?**
ყველას აძლევს წაკითხვას, ჩაწერას და წაშლას. ნებისმიერს შეუძლია მონაცემი დააზიანოს. წესია **მხოლოდ საჭირო უფლება**.

**22. რით განსხვავდება შეკუმშვა, არქივი და backup?**
შეკუმშვა (`gzip`) ფაილს **ამცირებს**. არქივი (`tar`) ბევრ ფაილს **აერთიანებს**. backup არის **დაცული ასლი სხვა ადგილას**, საიდანაც აღდგენა შეიძლება.

**23. სად სრულდება `scp`-ის ბრძანება და რატომ?**
**კლიენტზე**, რადგან გადაცემას კლიენტი იწყებს (`linuxlab` alias მხოლოდ კლიენტის `~/.ssh/config`-შია).

**24. რატომ არ კმარა ფაილის არსებობა სწორი შედეგის დასადასტურებლად?**
ვამოწმებთ **რაოდენობას, შიგთავსს, უფლებებს, ბმულებს**. ჩვენს checklist-ში `world-writable` თავიდან `3` იყო (ცრუ განგაში სიმბოლური ბმულების გამო) და ეს მხოლოდ **შედარებამ „მიღებული vs მოსალოდნელი"** აღმოაჩინა.
